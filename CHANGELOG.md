### [0.1.14](https://github.com/xFlawlessDev/alnair-router/compare/v0.1.13...v0.1.14) (2026-11-06)

### OpenAI Responses upstreams

- An `openai-compatible` connection can now speak either OpenAI wire API. A new **Wire API** selector in the connection form picks `Chat completions` (the default, `/chat/completions`) or `Responses` (`/responses`). This unlocks upstreams that only implement Responses, such as Azure OpenAI and several gateways.
- The Responses path has its own request body and its own stream: system messages become `instructions`, tools are declared flat, the output limit is `max_output_tokens`, and the reply arrives as a typed `response.*` event sequence rather than chat deltas. Usage counters (`input_tokens`, `output_tokens`, and the cached/reasoning splits) are translated onto the same internal shape, so usage rows, pricing and the dashboard work identically for both.
- The setting is rejected on every other provider family. Those stacks implement exactly one wire contract, so the flag would be a silent no-op.
- `temperature` and `top_p` are forwarded. The sampling knobs the Responses schema does not define (`presence_penalty`, `frequency_penalty`, `seed`, `stop`) are dropped rather than sent, because the endpoint rejects unknown fields.
- A stream that dies before its terminal event is reported as an error. Ending it normally would let the router serve a truncated answer as if it were complete.

### Reasoning

- Reasoning effort now reaches **every** provider family, including `openai-compatible`, which previously accepted the setting and then silently dropped it. When an upstream rejects the parameter, the request is retried without it instead of failing the turn.
- `POST /v1/responses` accepts `reasoning.effort`. It was previously not read at all, so a reasoning request sent to a Responses client was lost.
- The top tier is spelled per dialect. OpenAI treats `xhigh` and `max` as two distinct levels with `max` the highest, so the router's top tier now maps to `max` on the Responses API and keeps `xhigh` on chat completions.

### Usage and cost

- The **cache share of the input charge** is now stored per row (`cost_cache_usd`) and shown inside the Input row of both cost breakdowns, e.g. `$0.0012 uncached + $0.0025 cache read`. It is a slice of input, not an extra line, so the parts still add up to the stored total. Without it a cache-heavy workload read wrong: a prompt that was 99% cached looked like it had been billed at the full input rate.
- A **Cache hit** card on the usage summary reports the cached share of the prompt, with a popover splitting prompt tokens into cached and uncached. It appears on the Usage, Overview and self-service pages.
- Fixed an undercount in Anthropic-native billing. Anthropic reports its input buckets separately and its docs define total input as `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`; the router stored `input_tokens` alone. Cached tokens were reported while the prompt total they belonged to was not, so the cache share could read above 100%. Every provider now stores a prompt total that includes its cached tokens.
- Database migrations `0029` (wire API) and `0030` (cache cost) are additive, default safely, and leave existing rows reading exactly as before.

### [0.1.12](https://github.com/xFlawlessDev/alnair-router/compare/v0.1.11...v0.1.12) (2026-11-04)

### Search connections

- The connection form has a **Search path** field, so a provider that serves search somewhere other than `/search` can be configured from the dashboard. The value is normalized to a leading slash, and an empty field clears the column so the router falls back to `/search` instead of appending an empty string.
- Adding a search provider now puts it in the first fallback tier. Before, the dashboard never sent a tier, and the router leaves a connection with no tier out of `/v1/search` entirely, so a provider added from the picker silently never received a search request. This covers both duplicating a configured provider and creating one through the form. Chat providers still get no tier, and an existing connection keeps whatever it stored.
- The connection list shows a `search tier` badge for connections that opted in, with a tooltip naming the URL `/v1/search` actually calls.

### [0.1.11](https://github.com/xFlawlessDev/alnair-router/compare/v0.1.10...v0.1.11) (2026-11-03)

### ChatGPT/Codex sign-in

- A Codex connection is now created and authorized in one dialog. Choosing the ChatGPT preset opens a form with a name and a **Connect in browser** button, then waits for the login to finish. Before, the sign-in button never appeared in the dashboard.
- An existing Codex connection opens read-only: its endpoint and credential come from the provider login, so only the name can be changed, and the option to sign in again lives in the same form.
- Presets now fill in their own OAuth endpoints, so the dashboard no longer has to reproduce the provider's URLs. Previous builds failed with "token_url is required" because the form sent blanks.

### Search routing

- A connection can set the path its provider serves search on, which the router appends to the base URL. Providers such as Brave use `/web/search`; connections without a path keep the default `/search`, so existing setups do not change.
- `POST /v1/search` now falls back to search connections when the primary provider is out of quota, rate limited, or unreachable. Search connections are grouped into tiers, lowest first, and connections in one tier take turns. A 404 still fails fast: it usually means a wrong path, and falling back would hide it.
- Database migration `0027` adds the search path column and `0028` adds the tier. Both are additive and preserve existing connections.

### Aliases

- The reference-price picker in the alias dialog is searchable and caps how many rows it renders, so a catalog with thousands of prices stays usable.

### [0.1.10](https://github.com/xFlawlessDev/alnair-router/compare/v0.1.9...v0.1.10) (2026-11-03)

### ChatGPT/Codex subscription

- Added a `ChatGPT Plus/Pro (Codex)` connection that signs in with your ChatGPT subscription and serves the Codex models. The connection needs no API key.
- The Codex backend publishes no model list, so the router ships a built-in list of the models it served. That list is marked as a convenience in the probe API, the connectivity test, `GET /v1/models`, and the dashboard. It does not restrict which models you can request.
- This preset uses OpenAI's own Codex client identity, because the Codex backend only authorizes that application. Use it only with your own account and check the terms you agreed to. The picker, README, and roadmap show this warning.
- Database migration `0025` rebuilds the connections table to accept the new provider type. Existing connections, and the rows that reference them, are preserved.

### Search providers

- The provider picker has a new **Search** section with Exa, Firecrawl, and Tavily presets.
- Harnesses keep calling `POST /v1/search`. The router appends `/search` to each provider's base URL, so the harness does not need to know the provider's path.

### Aliases

- An alias can pin the stored price row that bills its requests. The pin takes precedence over the connection's pricing model and the requested model id. The dashboard offers it as a picker, and the default is to inherit the existing behavior.

### Reliability

- An HTTP 200 response that carries an HTML page, such as a login or captive-portal page, is now reported as an error. Before, it was treated as an empty or malformed completion and was hard to diagnose.
- The Anthropic-native provider was split into smaller modules. Behavior is unchanged.

## [0.1.9](https://github.com/xFlawlessDev/alnair-router/compare/v0.1.8...v0.1.9) (2026-11-01)

### Performance

- The router no longer burns about half a CPU core while idle on Windows and macOS. With the tray icon enabled, the desktop event loop now blocks until there is an actual tray, menu, or shutdown event instead of polling continuously.
- No configuration change is needed: the fix applies to every desktop run, and machines that relied on `--no-tray` to keep the process quiet can now use the tray without the cost.

## [0.1.8](https://github.com/xFlawlessDev/alnair-router/compare/v0.1.7...v0.1.8) (2026-10-27)

### Database upgrades

- Fixed startup failures on Windows-to-Linux upgrades caused by SQLx checksums differing only because migration files used CRLF instead of LF line endings.
- Existing application data is preserved. The router normalizes only an applied migration checksum that exactly matches the CRLF form of the same migration SQL; unrelated checksum mismatches remain errors.

## [0.1.7](https://github.com/xFlawlessDev/alnair-router/compare/v0.1.6...v0.1.7) (2026-10-27)

### Multimodal chat

- OpenAI-compatible chat requests can include audio, video, and file content parts, alongside text and images. Supported parts are forwarded in their original wire shape.
- Unsupported content parts and malformed media payloads now return a clear `400` error instead of being silently dropped.
- Media input is limited to OpenAI-compatible connections; incompatible provider types are rejected explicitly.

### Web search and fetch

- OpenAI-compatible chat requests can pass `web_search_options` through to providers that support built-in web search.
- Search responses remain provider-specific by default for compatibility. Add `?normalize=true` to `/v1/search` to request Alnair's common result shape.
- Connections can route `/v1/web/fetch` through a configured provider extract endpoint for pages that require JavaScript rendering. Local, SSRF-guarded fetching remains the default.
- The local fetch guard also blocks carrier-grade NAT addresses in `100.64.0.0/10`.

### Dashboard and reliability

- Connection settings expose the optional provider-backed web-fetch mode and extract path.
- Existing connections and clients retain their previous behavior unless they opt into the new features.

## [0.1.0](https://github.com/xFlawlessDev/alnair-router/releases/tag/v0.1.0) (2026-09-17)

First public release of Alnair Router, a self-hosted gateway for routing AI requests across providers.

- Route OpenAI-compatible chat and Responses API requests, and Anthropic Messages requests, through a single service.
- Configure provider connections, aliases, and ordered fallback combos, with retries and per-connection limits.
- Proxy embeddings, image, audio, video, moderation, and search requests; protect local web fetching against SSRF.
- Secure credentials and API keys, enforce per-key access and usage limits, and track usage and cost.
- Manage connections, keys, usage, settings, and backups from the embedded dashboard.
- Install and run the service with platform installers, npm packages, Docker, or the command-line interface.
